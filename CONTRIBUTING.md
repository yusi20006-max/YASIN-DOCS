# Contributing to YASIN-DOCS

YASIN-DOCS documents the architecture and operating knowledge of the Yasin Ecosystem.

## Documentation Rules

1. Prefer verified repository facts over assumptions.
2. Clearly distinguish current implementation from planned architecture.
3. Preserve project boundaries and ownership.
4. Record important architectural changes through an Architecture Decision Record when appropriate.
5. Keep cross-project documentation consistent with the affected repositories.
6. Do not copy implementation details into this repository when a link or project-specific document is sufficient.
7. Update the relevant project documentation when a cross-project interface changes.

## Change Process

For significant documentation changes:

```text
Identify scope
    -> Verify source repositories
    -> Update documentation
    -> Review cross-project impact
    -> Validate links and terminology
    -> Commit
```

## AI Contributions

AI coding agents may update this repository, but they must verify repository state before asserting implementation facts. When uncertain, the documentation should label information as provisional rather than inventing certainty.
